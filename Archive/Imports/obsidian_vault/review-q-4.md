# RQ 7-1
The architectural design phase provides a high-level overview of the system. Large/main components are listed, as well as relationships between components. Requirements play the biggest part and drive for these overviews (for instance, what components do we need to achieve our functional/non-functional requirements?).
During the detailed design phase components are broken down into more granular detail. The macro view provided in the architectural phase and the functional requirements are what drive the detailed design phase. The architecture provides a general map, while the functional requirements are addressed along the way.

# RQ 7-3
When we apply the technique of generalization, we try to single out the main characteristics of a system. This is similar to OO design because OO views a system as a collection of objects, meaning both methods try to draw out the main characteristics/things from a system.

# RQ 7-5
* Logical/Structural View - Object oriented decomposition of a system and highlights the relationship between classes
* Process View - Focuses on the run-time behavior of a system and deals with dynamic elements.
* Development View or Implementation View - Shows a system from the viewpoint of a programmer and is mainly concerned with software administration.
